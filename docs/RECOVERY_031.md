# 0.3.1 기능 안정화 — 사건 체크포인트

## 범위와 판정 경계

0.3의 신호 복구 연출, 도시 첫 진입 연출, 일곱 형체 연출을 지속 저장되는 사건 레코드로 옮긴다. 건축·외형·텍스처·음악·이펙트 자산은 추가하지 않는다. 이 묶음은 **기능 안정화의 첫 하위 단계**이며, 사용자 요청의 전체 안정화 완료와 다르다. 실제 실행 결과는 evidence/stability/VERIFICATION.txt와 GATES.md를 따른다.

## 상태와 저장 책임

- 사건 인스턴스 UUID, 사건 종류/ID, 원점, 차원, 관련 구조물 식별자, 상태, 체크포인트, 표시된 자막/음향 비트, 중단 횟수/사유를 Overworld SavedData에 저장한다. 전역 파일이나 원본 월드 경로를 게임 진행 데이터에 넣지 않는다.
- NOT_STARTED는 레코드가 없는 상태다. PREPARING → ACTIVE → PHASE_1 → PHASE_2 → RESOLVING → COMPLETED를 사용한다. 이탈은 SUSPENDED, 잘못된 저장 상태는 FAILED_RECOVERABLE로 다룬다. 프레임 단위 복원을 하지 않는다.
- 체크포인트는 0 / 65 / 130 / 195 / 240 게임 tick이다. 완료한 경계에서 재구성하며 그 이전 연출 전체를 처음부터 재생하지 않는다. 이미 확인한 자막·음향의 비트는 체크포인트와 별도로 유지한다.
- 마지막 경계의 서버 확인 후에만 `cityShockTriggered=true`를 기록한다. 시작 직후 true로 확정하던 0.3 동작을 바꿨다.
- 단서, 신호 복구 사실, 도시 방문/책 기록, 복귀 위치, 플레이어 인벤토리는 연출 레코드와 별개다. 복구기가 이를 이전 값으로 되돌리지 않는다.
- 이 세 연출은 보상 지급·아이템 소비·실제 NPC 구조·블록 수정 자체를 수행하지 않는다. 따라서 없는 보상 시스템을 검증했다고 주장하지 않는다. 신호 복구 상호작용에서의 레드스톤 소비와 월드/플레이어 저장 간 강제 종료 원자성은 별도 미검증 게이트다.

## 서버와 클라이언트

서버가 사건과 체크포인트를 소유한다. 클라이언트는 현재 연결에 발급된 일회성 lease UUID로 같은 단계 또는 바로 다음 단계만 확인한다. 오래된 연결 토큰, 다른 사건 UUID, 단계 건너뛰기, 완료 뒤 중복 확인은 진행을 변경하지 않는다. 확인 패킷은 아이템·선택·엔딩·관계 사실을 지급하지 않는다.

중요 경계와 표시 확인은 SavedData를 dirty 표시한 뒤 디스크 저장을 호출한다. 이 호출을 전체 Minecraft 저장 파일에 대한 원자적 트랜잭션이나 OS 전원 차단 내구성으로 간주하지 않는다. 일부 핵심 필드 누락·지원하지 않는 사건 종류·중복된 저장 사건은 구체적 오류로 중단한다. 알 수 없는 enum과 범위를 벗어난 체크포인트는 완료를 주지 않고 안전 단계로 복구한다.

재접속·차원 이동·죽음·메뉴 열기·현장 이탈은 연출 소유 형체와 해당 모드 환경음을 정리한다. 경계 자체는 남는다. 조건을 다시 만족하면 재개한다. 경과 시간만으로 사건이 완료되거나 영구 실패하지 않는다. lease 만료는 연결 복구용이며 이야기 타이머가 아니다.

일곱 임시 형체는 서버 NPC가 아니라 클라이언트 장면 배우다. `ownerEventId`와 역할을 부여하며, 연결이 끊기면 저장 엔티티로 남지 않는다. 복원 시 체크포인트에 맞춰 최대 7개만 만든다. 이를 일반 NPC 레지스트리의 완성으로 간주하지 않는다.

## 귀로꾼 조우의 별도 수정

소유 플레이어가 접속하지 않았거나 사망/다른 차원에 있을 때 AI와 조우 수명 카운터를 멈춘다. 저장된 정규 엔티티 UUID와 다른 소유 개체, 완료한 조우의 남은 개체는 제거한다. 기존의 현장 이탈로 첫 만남을 끝내는 규칙은 유지한다.

아직 남은 과제: 저장 UUID가 가리키는 개체가 정말 사라졌는지와 단순 청크 미로드인지 구분하는 탐색/재생성, 귀로꾼 각 행동 단계의 실제 중단/사망 회귀, 일반 NPC 소유권 레지스트리. 현재의 무결성 명령은 장면 레코드 검사이며 전체 NPC/구조물/엔딩 무결성 검사기가 아니다.

## 저장 마이그레이션

저장 형식은 **4**다. 기존 1·2·3을 명시적으로 이어받으며 미래 형식은 오류를 낸다. 0.2의 형식 2에서 없던 `cityShockTriggered`는 false다. 0.3에서 이미 true인 값은 과거 완료 사실로 보존한다. 과거 형식에서 이미 신호 복구/도시 방문을 마친 연출도 완료로 이관한다. 이미 겪은 장면을 업그레이드 후 갑자기 다시 보여주지 않기 위한 정책이다.

0.3은 시작과 완료를 한 boolean으로 기록했으므로, 과거 저장의 true가 실제 중단이었는지는 소급 판별하지 않는다. 새 체크포인트 복구는 새 레코드가 만들어지는 사건부터 적용한다.

도시 배치 revision 1/2와 셀 순서는 변경하지 않는다. 형식 4로 진행한 월드를 0.3/0.2로 다운그레이드하는 작업은 이번 복구 시험이 아니다. 제공하는 ROLLBACK.sh는 지정한 JAR 복사본만 0.3으로 복원한다.

## 진단과 테스트 접근

`-Dwhileaway.debug=true`로 실행한 개발 서버의 권한 2 이상에서만 `/whileaway debug events`, `/whileaway debug integrity`를 등록한다. 일반 설치에서는 debug 분기가 보이지 않는다. 이벤트 로그에는 플레이어/사건/인스턴스/상태/경계/중단 사유가 포함된다.

`RecoverySmoke`는 명시적인 개발 실행 속성에서만 활성화한다. 전용 월드를 만들고, 사건 시작 **전에** 준비 상태를 저장한다. 중간 경계 2에서 테스트 JVM만 `Runtime.halt`로 종료하며 사건 시작 뒤 정상 종료 저장을 하지 않는다. 복구 실행은 같은 저장을 다시 연다. 인벤토리 비교용 다이아몬드 27개, 진행 준비, keepInventory=true는 테스트 조건이며 일반 게임 설정을 변경하지 않는다.

클라이언트 테스트는 시작 전 모든 소리 분류와 내레이터를 끈다. 재생음의 중복 호출은 저장 비트와 로그로 검사하며 청감 평가와 구분한다.

## 이후 순서 유지

남은 A/B/D/E 강제 종료 지점과 다른 주요 사건의 실제 클라이언트 회귀 → 필수 구조물 레지스트리·대체 경로 → 일반 엔티티 누락 재구성 → 소비/보상 멱등성 → 현재 전체 진행 회귀 → 다음 핵심 기능. 최종 아트는 계속 보류한다.
