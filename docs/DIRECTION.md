# 공포·서사·연출 제작 기준

## 목표와 현재 위치

최신 개발 기준은 [FUNCTION_FIRST.md](FUNCTION_FIRST.md)이며 이 문서의 이전 계획보다 우선한다. 오버월드의 평범한 생존 생활이 지속적인 핵심 무대다. 전용 도시는 서사 밀도가 높은 장소로 사용하되, 전체 경험을 테마파크형 맵으로 만들지 않는다. 0.3 개선판 이후 최종 아트는 보류하고 체크포인트·진행 경로·예외 복구와 전체 캠페인 기능을 먼저 안정화한다.

기준은 연출 효과의 개수가 아니라 **앞서 본 사물이 나중에 다른 뜻으로 돌아오는가**다. 전용 차원의 첫 구역과 전체 도시 캠페인을 구분한다. 다중 엔딩은 아직 구현된 것으로 취급하지 않는다.

## 공포 곡선

| 구간 | 플레이어 경험 | 원인과 통제 |
|---|---|---|
| 진입 | 빈 역, 방향이 맞지 않는 노크 | 발견 전에는 모드 공포 사건을 시작하지 않는다. |
| 조사 | 자신이 멈춰도 한 박자 더 걷는 소리 | 고유 단서가 공포 단계를 연다. 독서 시간을 빼앗지 않는다. |
| 복구 | 돌아온 신호와 돌아오지 않은 사람 | 복구라는 플레이어 행동이 후속 연출을 직접 일으킨다. |
| 도시 전반부 — 예정 | 안전하다고 믿었던 길의 규칙이 어긋남 | 똑같은 놀람을 반복하지 않고, 바뀐 규칙을 공간으로 가르친다. |
| 중반 절정 — 예정 | 대피 실패 현장과 다수 괴물의 원인 발견 | 높은 압박 뒤에는 긴 회복 구간과 슬픈 기록을 배치한다. |
| 후반 — 예정 | 무엇을 구할 수 있는지 이해한 뒤 선택 | 갑작스러운 선악 버튼이 아니라 누적 행동이 엔딩을 결정한다. |

## 대표 장면: 신호가 돌아오는 순간

현재 코드의 12초 연출은 신호 복구를 원인으로 시작한다. 2.25초에 옆 공간에서 노크가 난다. 약 3.25초부터 재가 떠오르고 첫 문장 "신호는 돌아왔다."가 나온다. 5.5초에 반대편 발소리가 이어진다. 7.5초에 뒤쪽 먼 숨소리가 들리고, 8초부터 "돌아올 사람의 이름은 없었다."가 나온다. 화면 가장자리는 천천히 어두워졌다가 회복한다. 12초 뒤 연출이 끝나고 플레이어의 조작은 그대로 남는다.

이것은 첫 연출 기능의 검증용 장면이다. 최종판에서는 실제 신호등 점등, 기계 부품 동작, 창 너머 실루엣의 시선 가림, 거리별 잔향과 후속 동선이 같은 타임라인에 연결되어야 한다. 현재 구현에 없는 부분을 스크린샷이나 설명으로 완성된 것처럼 대체하지 않는다.

## 귀로꾼의 인과관계

몸은 문을 통과하려고 접은 자세에서 굳었다. 발은 집으로 향하지만 상체는 역을 돌아본다. 인간이 괴물을 피해 도망쳤다는 정보보다, 인간이 끝내 떠나지 못한 이유를 먼저 보여준다. 최종 개인 기록은 가족의 기다림과 통제된 대피 신호의 모순으로 연결한다.

현재 행동은 관찰 가능한 경고 구간 → 가까이 접근하면 공격 전조 → 추격 → 이탈/종료로 구현했다. 광범위한 괴물군을 단순 외형 변형으로 늘리지 않는다. 다음 개체는 귀로꾼과 다른 이동 규칙·반격 수단·과거 원인을 가진다.

## 시적 힌트의 밀도

- 기록 하나에는 이미지 하나와 실제 행동 단서 하나를 둔다.
- 중요한 퍼즐은 문장 하나를 해석해야만 풀리게 하지 않는다. 건축물, 사물의 위치, 소리 중 두 가지가 같은 결론을 가리키게 한다.
- 슬픈 장면 직후 전리품 팝업이나 희화화된 점프스케어를 넣지 않는다.
- 주민의 선택에는 당시의 정보 부족, 자원 부족, 가족 관계라는 이유를 남긴다. 설명문 대신 서로 모순되는 생활 기록을 교차 배치한다.

## 초기 제작 순서 (0.1 계획; 폐기된 우선순위; 최신 순서는 FUNCTION_FIRST.md 참고)

1. 현재 폐역의 생존 전체 진행, 재접속, 사망, 장거리 이탈, 두 클라이언트 조우를 검증한다.
2. 역 외형과 괴물 재질을 고유 아트로 교체하고 신호기 실제 상태를 모델/빛에 연결한다.
3. 도시 차원 한 구역을 만들고 입장·복귀·저장·재생성 방지를 검증한다.
4. 서로 다른 행동을 가진 괴물 3종과 첫 인간 관계/선택을 추가한다.
5. 엔딩 상태 그래프를 구현한 뒤 장과 구역을 확장한다. 히든 해피 엔딩은 수집률만이 아니라 인물 이해와 구체적인 구조 행동을 요구한다.

## 의존성 원칙

현재 필수는 GeckoLib 하나이며 실제 빌드/클라이언트에서 사용한다. 고유 모델과 애니메이션을 담당한다. 조명·잔향·성능 모드는 선택적 호환 대상으로 검토하되 기본 진행을 외부 모드의 유무에 종속시키지 않는다. 고급 셰이더 전용 장면을 기본판 완성으로 세지 않는다. 새 의존성은 Minecraft/로더 버전과 서버 로딩을 확인한 뒤 추가한다.
