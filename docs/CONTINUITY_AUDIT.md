## 누락 위험 분류와 대응

1. **대화→문서:** 사용자 결정이 DECISION_LOG와 추적표에 없는지 확인한다. 대화 속 브레인스토밍을 확정 요구로 올리지 않는다.
2. **문서→작업:** 이번 WO에 해당하는 요구사항 ID가 하나도 언급되지 않은 경우 검토하고, 범위 밖이면 DEFERRED로 남긴다.
3. **작업→코드:** 설계 단계/임시 자산/테스트 helper를 본편 콘텐츠 완료로 오인하지 않는다. 실제 path와 commit SHA로 기록한다.
4. **코드→검증:** 자동 PASS·사용자 체험·미검증을 분리하고, 실패나 미완료 증거도 남긴다.
5. **버전/브랜치:** README/AGENTS의 과거 '현재', '다음'은 역사적 사실이다. 현 HEAD·schema·V2-03 work 상태를 읽는다.
6. **중단/재개:** PR·작업 종료 때 미완료 ID, 검증 실패, 다음 정확한 시작 단계 및 소급 불가 제약을 함께 남긴다.
