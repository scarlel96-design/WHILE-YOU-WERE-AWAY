## Semantic contract

Runtime integration changes WHEN observation can be committed: cp3 requires complete old-pattern playback plus explicit equipment interaction; cp5 requires complete response playback plus explicit equipment interaction. Emission alone no longer implies player observation. This is an intentional player-interaction gate, not a new durable fact. Old saved cp3/5/6 remain accepted; no retroactive replay requirement.

ReturnNetworkPlayback delegates canonical pulse order to existing Support ReturnNetworkSignal. Runtime:10tick lead-in,12tick SHORT,16gap,12SHORT,16gap,36LONG. At nominal20TPS:0.5s lead,0.6s/0.8s/0.6s/0.8s/1.8s. Tuning is not narrative canon; low TPS stretches wall time. Every server Post tick drives playback, independently of10tick NPC navigation. Missed/duplicate tick, readiness loss or carrier rejection cancels the entire transient session. Next start uses a new UUID and complete pattern. Nothing is serialized.

No persistent LIT toggle, block writes, camera movement, force load, teleport, new entity/reward/monster or audio framework. The existing explicit intervention setBlock remains unchanged.

Participant: exact canonical NPC, same dimension, arrived at STAND; original session observer alive/non-spectator/within6blocks; environmentReady. Confirmation additionally uses existing5block interaction reach and same observer UUID. Signal packets are technical delivery attempts, NOT claims about human perception. The new neutral completion prompt invites inspection without spelling out pattern order. Existing evidence text remains after confirmed observation.

Completed event stays quiet; no automatic ambient replay implemented. cp5+ receipts are never generated by the playback driver.
